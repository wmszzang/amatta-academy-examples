# EP.5 — 좌표는 어디서 읽는가: 프레임 · 2D 회전 · 강체 변환

기구학 단원의 **첫 편**입니다. 영상: (발행 후 기입) 같은 점이 프레임마다 다른 좌표로 읽히는 이유를 실물 로봇 팔로 보고, 단위원에서 출발해 **회전행렬 R(θ)** 과 **강체 변환 p′ = Rp + t** 를 유도한 뒤, 연습장 문제 #226(정사각형 30° 회전 + 이동)을 네 꼭짓점 전부 검산합니다. 후반은 각도 규약 — 도/라디안, [−π, π] 래핑과 최단 각오차(#477), atan2 사분면 표, 원형 평균(#558).
영상에서 다룬 숫자가 그대로 코드 상수로 들어 있고, 세 언어의 계산 프로그램이 모두 같은 `points.csv` · `angles.txt` 를 만듭니다.

| 입력 | 계산 | 기대 결과(검산) |
|---|---|---|
| 한 변 1인 정사각형 (0,0) (1,0) (1,1) (0,1) · 회전 30° · 이동 t = (1, 0.5) | **강체 변환** p′ = R p + t (회전 후 이동) | (1.0000, 0.5000) · (1.8660, 1.0000) · (1.3660, 1.8660) · (0.5000, 1.3660) |
| 툴 프레임 자세 = R(30°), t = (1, 0.5) · 툴에서 읽은 점 (1, 0) | **프레임 왕복** 툴 → 베이스 | (1.8660, 1.0000) |
| 베이스에서 읽은 점 (2, 1) | 베이스 → 툴 = Rᵀ(p − t) · 다시 베이스로 | (1.1160, −0.0670) → (2.0000, 1.0000) 정확 복원 |
| R(30°) | **직교성** RᵀR · det · trace | RᵀR = [[1, 0], [0, 1]] · det = 1.0000 · trace = 1.7321 (= 2cos30°) |
| 목표각 3.0 rad · 현재각 −3.0 rad | **최단 각오차** wrap(target − current) | −0.2832 (단순 뺄셈 6.0은 오답) · (0.1, −0.1) → 0.2000 |
| 헤딩 [170°, −170°] · [10°, −10°, 350°] | **원형 평균** atan2(Σ sinθ, Σ cosθ) | 180.0000 (단순 평균 0은 오답) · −3.3637 (단순 평균 116.67은 오답) |
| 359° | **래핑** [−180°, 180°] | −1.0000° |

핵심 한 줄(영상 §회전행렬): **R의 두 열은 돌아간 새 x축·새 y축**이다. 그래서 두 열이 서로 직각·길이 1 → RᵀR = I → **역행렬 = 전치행렬**, det = 1.
Python판의 `to_tool()` 이 그 사실을 그대로 쓴 함수입니다(이동량을 빼고 Rᵀ를 곱한다).

- 출력 파일: `points.csv` (x, y, xr, yr — 원본과 변환 후) · `angles.txt` (각도 도구 셋의 결과) · `frames2d.png` / `frames.svg` (그래프)
- ⭐ **순서에 주의**: 회전 → 이동입니다. 먼저 밀고 나서 돌리면 (1, 0)이 (1.8660, 1.0000)이 아니라 (1.4821, 1.4330)에 떨어집니다(`frames2d.py` 출력의 `move-then-rotate` 줄).

```
[1] 계산 프로그램 실행 (Python / C / C++ 중 하나) ──→ points.csv · angles.txt
[2] python visualize.py ──→ frames2d.png (정적)  /  --frames → frames/frame_00..11.png + wrap_dial.png
    또는   cpp/plot_svg ──→ frames.svg
```

## 1) Python으로 실행

**준비물**: [Python 3](https://www.python.org/downloads/) (설치 시 "Add python.exe to PATH" 체크)

```
cd python
python frames2d.py
```

`tool(1,0)->base(1.8660, 1.0000)`, `base(2,1)->tool(1.1160, -0.0670)`, `->back(2.0000, 1.0000)`,
`RtR = [[1.0000, 0.0000], [0.0000, 1.0000]]`, `ang_err(3.0,-3.0)=-0.2832`, `circ_mean([170,-170])=180.0000` 이 나오면 성공입니다.
(한글이 깨지면 `set PYTHONIOENCODING=utf-8` 후 다시 실행하세요.)

## 2) C로 실행

**준비물**: 둘 중 하나

## 직접 실험해 보기

코드 안의 상수를 바꿔 보세요.

- **회전과 이동 순서 바꾸기**: `rigid_2d` 안에서 이동을 먼저 더하고 회전하면 (1, 0)이 (1.4821, 1.4330)으로 갑니다 — 순서가 답을 바꿉니다
- **회전 중심 옮기기**: 원점이 아니라 점 c를 중심으로 돌리려면 p′ = R(p − c) + c — c를 빼서 원점으로 옮기고, 돌리고, 다시 더합니다
- **RᵀR 출력해 보기**: `orth_check(30)` 의 결과가 항등행렬입니다. 각도를 바꿔도(45, 120, −60) 항상 항등행렬 — 이것이 역행렬 = 전치행렬의 근거
- **래핑 없이 각오차 재보기**: `ang_err` 에서 `wrap` 을 빼면 (3.0, −3.0)에 6.0이 나옵니다 — 거의 한 바퀴를 헛도는 오답

### 흔한 실점

- 도(degree)를 라디안으로 바꾸지 않고 `sin`/`cos`에 넣는다 (코드의 삼각함수는 라디안만 받는다)
- 회전행렬 부호가 뒤바뀐다: x′에는 **−sinθ**, y′에는 **+sinθ**
- 점 목록 중 일부만 변환한다
- `atan2` 인자 순서를 (x, y)로 쓴다 — **(y, x)** 가 맞다
- 각오차를 [−π, π]로 접지 않는다
