# EP.14 — 해석해냐 수치해냐, 속도냐 힘이냐 (역기구학·자코비안 끝내기)

로봇소프트웨어개발기사 실기 대비. **새 개념은 없다** — 지문에서 계산을 고르는 판별과,
고른 계산을 제출물(수치 + 요구 그래프)까지 닫는 완주만 다룬다.

영상: `자격증 · 로봇소프트웨어개발기사 · 실기 EP.14`
연습장: https://www.techrraforming.com/practical?cert=RobotSoftware

### 판별 결정 트리

```
지문 첫 줄
├─ 관절속도 rad/s 가 있다        → v = J qdot
├─ 힘 N 이 있다                  → tau = J^T F      (전치 필수)
├─ "닿는가 / 얼마나 잘"          → reach_manip      (r, w, kappa)
├─ 초기각 + "반복하라"           → newton_dls       (검사/갱신 횟수 구분)
├─ 목표 좌표만                   → ik2              (두 분기)
├─ 점군 + 넓이                   → hull -> shoelace (오목부를 메운다는 점 명시)
└─ 질량 + 지지면                 → com_projection   (부호 있는 여유)
```

## 실행

### Python (3.9+)
```bash
cd python
python run_all.py            # 다섯 지문 콘솔 출력 + output-python/*.csv
python visualize.py          # 여섯 장면 PNG
python visualize.py --frames # 장면마다 12 fps 프레임 시퀀스
python visualize.py --case hull
```
`visualize.py`만 matplotlib이 필요하다(`pip install matplotlib`). 계산은 표준 `math`만 쓴다.

### C (C99)
```bash
gcc -std=c99 c/kin14.c -o kin14_c.exe -lm
./kin14_c.exe
```

### C++ (C++11)
```bash
g++ -std=c++11 cpp/kin14.cpp -o kin14_cpp.exe
./kin14_cpp.exe
```

세 언어의 콘솔 출력은 소수 4자리에서 동일하다(Windows MinGW로 실측 대조).

## 출력 CSV 규약

| 파일 | 열 |
|---|---|
| `p1_ik.csv` | `case, elbow, th1_deg, th2_deg, th1_rad, th2_rad, fk_x, fk_y, status` |
| `p2_workspace.csv` | `th1_deg, th2_deg, x, y, in_fence` (+ `hull.csv`, `area.txt`) |
| `p3_vel_force.csv` | `th1_rad, th2_rad, dq1, dq2, vx, vy, Fx, Fy, tau1, tau2, detJ, w, kappa` |
| `p4_numeric.csv` | `start_th1_rad, start_th2_rad, lam, iters, updates, th1_raw_rad, th2_raw_rad, th1_wrapped_rad, th2_wrapped_rad, converged` |
| `p5_stability.csv` | `pose, com_x, com_y, margin, stable` |

- 모든 수치는 **소수 4자리 반올림**, 각도 열은 이름에 단위(`_deg` / `_rad`)를 적는다.
- ⚠️ **`iters` 는 오차 검사 횟수**다. 각도 갱신 횟수는 그보다 1 적다(`updates` 열).
- 내부 계산은 반올림하지 않는다. 출력할 때만 자른다.

## 실험해 볼 것

1. `newton_dls` 의 `lam` 을 `0.0 → 0.05 → 0.2` 로 올려 보라. 수렴 횟수와 중간 오차가 어떻게 바뀌는가.
   `λ=0.05`, 시작 `(0,0)` 의 오차는 `1.8028 → 0.6761 → 4.2474 → …` 로 **단조 감소하지 않는다**.
2. `ik2` 의 클램핑(`c2` 를 −1~1 로 자르는 두 줄)을 지우고 `(3.0, 2.0)` 을 넣어 보라.
3. `sweep_points` 의 표본 수를 25에서 901로 늘리면 껍질 넓이는 그대로지만 격자 점유 면적이 달라진다.
4. `torque()` 를 `velocity()` 로 바꿔 부르면 `(−5.4010, 6.8864)` 가 나온다 — 정답과 `12.1046` 만큼 어긋난다.

## 흔한 실점

| 실점 | 내용 |
|---|---|
| 전치 누락 | `J F` 와 `Jᵀ F` 는 둘 다 숫자 두 개라 모양만 보면 구별되지 않는다. 첫 토크에는 **첫 열**의 두 값을 쓴다. |
| 도달 불가에 예외 | 지문이 `UNREACHABLE` 출력을 요구하면 예외를 던지지 말고 문자열을 반환한다. |
| 과한 클램핑 | 클램핑은 부동소수 미세 오차만 경계에 맞추는 것이다. 실제로 닿지 않는 목표를 끌어들이면 오답이다. |
| 횟수 정의 | "몇 번 반복했는가"의 답이 검사 횟수인지 갱신 횟수인지 밝히지 않으면 감점된다. |
| 래핑 누락 | 수치 IK가 `(−11.5288, 30.2295) rad` 처럼 여러 바퀴 감긴 값을 낼 수 있다. 반환 전에 되감는다. |
| 껍질 = 도달면적 | 볼록껍질 `11.0790 m²` 는 오목부를 메워 격자 추정치 `7.1523 m²` 보다 약 55% 크다. |
| 널공간 오해 | 널 방향은 **순간** 속도가 0인 방향이다. `0.15 rad` 유한 이동이면 손끝이 `0.004536 m` 어긋난다. |
| 중력항 혼동 | `τ_g=(68.2141, 7.9505)` 는 링크 자중 보상이고, `τ_cmd=(58.9854, 3.3535)` 는 거기에 목표 힘의 토크를 더한 값이다. |
